## 이 저장소에서의 TDD 조정

기본 역할 지침은 TDD를 전제하지만, **이 저장소에는 동작하는 테스트 스위트가 없습니다.**
없는 스위트를 근거로 GREEN을 선언하지 마십시오.

우선순위:

1. **테스트를 쓸 수 있는 대상이면 씁니다.** 순수 로직 — 특히
   `server/src/services/assignment_engine.js`, `dispatch_engine.js` — 는 DB 없이 검증
   가능하므로 테스트 작성 대상입니다. 서버에 러너가 없으므로 `node --test`(내장)를 쓰고,
   `server/package.json`에 `"test": "node --test"`를 추가하십시오. 이때 러너 도입 사실을
   결과 보고에 명시하십시오.
2. **테스트가 어려운 대상(화면, 라우트 배선, 마이그레이션)은 실행 검증으로 대체**하고,
   무엇을 어떻게 확인했는지 명령과 출력을 그대로 보고하십시오.

## 변경 유형별 최소 확인선

| 변경 | 확인 |
|---|---|
| Flutter 코드 | `cd ubf_app && flutter analyze` — 무경고 |
| 서버 코드 | `node --check <파일>` + 서버 기동 후 실제 `curl` |
| 새 라우터 | `src/index.js`에 `app.use` 등록 확인 + 200 응답 확인 |
| 마이그레이션 | 실제 적용 후 출력에 `✗` 없음 + **재실행해도 `✗` 없음**(멱등성) |
| UI 문자열 | `app_en.arb` / `app_ko.arb` / `app_es.arb` 3개 모두 갱신 |

`flutter analyze`는 경고가 하나라도 남으면 완료가 아닙니다.

## 구현 시 자주 깨지는 지점

- 라우터를 만들고 `src/index.js` 등록을 빠뜨림 → 조용한 404
- `UserRole`(Dart `enum { director, admin, participant }`)과 서버 문자열 불일치 →
  한쪽만 고치면 권한이 조용히 틀어집니다. 항상 양쪽을 함께 확인하십시오.
- ARB 3개 중 1~2개만 갱신
- `ApiClient`의 플랫폼별 토큰 저장 분기를 "정리"하다 제거 → macOS·웹 로그인이 깨집니다.
  이 분기는 의도된 것입니다.
- Google 로그인 흐름(네이티브 idToken / 웹 accessToken 이원화) 수정 시 한쪽만 검증
