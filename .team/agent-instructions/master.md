## 이 저장소에서 태스크를 만들 때

**태스크는 3축(`ubf_app` / `server` / `migrations`) 중 어디를 건드리는지 본문에 적으십시오.**
Conductor가 분해와 병렬 배정을 판단하는 근거입니다.

## `--exclusive`로 제안해야 하는 태스크

DB는 worktree로 격리되지 않고 모든 태스크가 같은 Neon 인스턴스를 공유합니다.
아래는 단독 실행해야 합니다.

- **스키마를 변경하는 태스크** (`ubf_app/supabase/migrations/`에 파일 추가)
- 기존 데이터를 대량으로 읽거나 갱신하는 태스크

동시에 두 개 이상 배정되면 마이그레이션 번호가 충돌하고 DB 상태가 서로를 덮어씁니다.

## 순차 의존으로 묶어야 하는 것

기능 하나가 3축을 모두 건드릴 때는 `--depends-on`으로 순서를 강제하십시오.

```
스키마 → API → 화면
```

세 개를 병렬로 풀면 화면 Agent가 확정되지 않은 API 응답 형태를 가정해 재작업이 납니다.

`app_en/ko/es.arb` 또는 `server/src/index.js`를 동시에 건드리는 태스크가 둘 이상이면
역시 순차로 묶으십시오 — 이 저장소의 rebase 충돌 다발 지점입니다.

## 진행 상황을 보고할 때

이 저장소에는 동작하는 테스트 스위트가 없습니다 (`widget_test.dart`는 플레이스홀더,
서버에는 러너 없음). Conductor가 "테스트 통과"만 근거로 완료를 보고했다면 그대로
사용자에게 전달하지 마십시오. 실제 검증 근거(`flutter analyze` 출력, `curl` 응답,
마이그레이션 재실행 결과)를 확인하고 전달하십시오.
