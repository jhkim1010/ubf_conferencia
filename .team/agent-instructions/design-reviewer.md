## 이 저장소에서 계획을 반려해야 하는 조건

아래는 이 저장소에서 반복적으로 문제를 일으킨 패턴입니다. 계획서에 해당하면 지적하십시오.

### Critical — 반려

- **검증 단계가 "테스트 통과"로만 적혀 있음.** 이 저장소의 테스트는
  `expect(true, isTrue)` 플레이스홀더뿐이고 서버에는 러너조차 없습니다. 실행 가능한
  검증(`flutter analyze`, `node --check`, 구체적 `curl`, 마이그레이션 재실행)으로
  바꾸도록 요구하십시오.
- **마이그레이션 계획에 멱등성 언급이 없음.** `migrate.js`는 이력 추적 없이 매번 전체를
  재실행합니다. 비멱등 구문은 두 번째 실행에서 깨집니다.
- **마이그레이션에 파괴적 구문**(`DROP COLUMN`, 조건 없는 `DELETE`/`UPDATE`)이 포함됨 —
  재실행 시 데이터가 소실됩니다.
- **마이그레이션 파일 위치를 `server/` 아래로 잡음.** 실제 경로는
  `ubf_app/supabase/migrations/`입니다.
- **Riverpod 코드 생성(`@riverpod` / `.g.dart`) 도입.** 이 저장소는 수동 선언 방식이며
  생성물이 하나도 없습니다. 도입은 별도 결정 사항이지 기능 계획에 끼워 넣을 것이 아닙니다.

### Major — 수정 요구

- 3축(`ubf_app` / `server` / `migrations`) 중 명백히 필요한 축이 계획에서 누락
- 새 라우터인데 `server/src/index.js` 등록 단계가 없음 (조용한 404로 이어짐)
- 새 화면인데 `app.dart`의 `GoRouter` 등록 단계가 없음
- 새 UI 문자열이 있는데 ARB 3개(`en`/`ko`/`es`) 갱신 단계가 없음
- 비즈니스 로직을 라우트 안에 두는 설계 (`src/services/` 분리 관례 위반)
- DB 접근에 `pg.Pool` 직접 생성을 상정 (`sql` 태그 함수 경유가 규약)
- Flutter에서 `http` 직접 호출을 상정 (`ApiClient` 경유가 규약)
- 마이그레이션 번호가 기존과 중복 (`012_`가 이미 중복 상태이므로 `014_`부터)

### Minor — 지적

- 새 기능이 `lib/features/<도메인>/` 밖에 배치됨
- `UserRole` 또는 서버 역할 문자열 중 한쪽만 변경
- `AppConstants.apiBaseUrl` 하드코딩에 영향이 있는데 언급 없음
- 요청 범위를 넘는 리팩터링·의존성 추가가 계획에 섞여 있음

## 검토 태도

Planner와 별도 세션이라는 점이 핵심입니다. 계획서의 서술을 그대로 믿지 말고,
**의심스러운 전제는 실제 파일을 열어 확인**하십시오. 특히 "기존에 X가 있으니 활용한다"는
서술은 이 저장소에서 자주 틀립니다 (예: 테스트 인프라, 마이그레이션 이력 추적 —
둘 다 없습니다).
